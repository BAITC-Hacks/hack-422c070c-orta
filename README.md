# AI Sana Challenge Hub

**Трек «Образование» · HackAlem AI · Кейс: «AI Sana Challenge Hub: от бизнес-задачи к решению»**

Платформа, которая помогает представителю бизнеса превратить короткий черновик задачи в полноценную карточку с прозрачным рейтингом, опубликовать её в общем каталоге и вручную выбрать студенческую команду среди откликов.

## 1. Что сделано

Проверено по факту в коде (`app/`, `lib/`) — реализовано:

- Ввод черновика бизнес-задачи, включая 5 готовых примеров для быстрого теста (`SEED_DRAFTS` в `lib/seed.ts`, кнопки в `app/page.tsx`).
- Вызов OpenAI API для анализа черновика и генерации ≥3 уточняющих вопросов по 7 категориям (`app/api/clarify/route.ts`), с валидацией: если модель вернула меньше 3 вопросов или невалидный JSON — эндпоинт возвращает явную ошибку, а не тихий сбой.
- Вызов OpenAI API для сборки структурированной карточки из черновика и ответов (`app/api/card/route.ts`) — поля, для которых данных не хватило, остаются пустыми.
- Ручное редактирование любого поля карточки с мгновенным пересчётом рейтинга (`updateCardField` в `app/page.tsx`).
- Детерминированный расчёт рейтинга 0–100 по 7 взвешенным категориям (`lib/rating.ts`) — чистая функция, без обращения к ИИ.
- 4 уровня готовности (черновик / рабочая / готовая / приоритетная), вычисляемые по итоговому баллу.
- Публикация задачи в каталог с сортировкой по рейтингу (`publishTask`).
- Каталог с фильтрами по теме и уровню готовности (`filterTopic`, `filterReadiness` в `app/page.tsx`).
- Форма отклика команды: идея, план, ссылка (`TeamResponseForm`); число откликов не ограничено.
- Ручной выбор бизнеса по каждому отклику — кнопки "Выбрать команду" / "Отклонить" (`decideResponse`); в коде нет ни одной функции автоматического назначения.
- В карточке отклика бизнес видит не только идею, но и профиль команды (интересы, навыки, технологии), план и кликабельную ссылку на прототип — достаточно данных для осознанного выбора.
- Выбор роли при входе без логина ("Я представитель бизнеса" / "Я студенческая команда") — переключает видимую часть интерфейса, аккаунты и пароли отсутствуют.
- Визуальный индикатор "ИИ-помощник заполнил по вашим ответам" на экране карточки.
- Дашборд-layout в 3 колонки: слева блок "Мой аккаунт" (редактируемое имя, аналитика — опубликовано/откликов/принято у бизнеса, задач/тем у команды) и навигация (свои задачи у бизнеса / темы каталога у команды), в центре основной сценарий, справа лента последних откликов "Активность".
- У студенческой команды в каталоге — кнопка "Подробнее о задаче", раскрывающая все поля карточки (потребность, данные, ограничения, критерии успеха, контакт, формат связи) перед отправкой отклика.
- Полный набор seed-данных: 5 черновиков, 5 готовых карточек с реальным рейтингом, 5 профилей команд, 5 откликов с разными статусами (`lib/seed.ts`) — каталог заполнен сразу при открытии.
- Визуальная схема сценария из 7 шагов на экране выбора роли (`StepsDiagram`).
- Защита от зависания: таймаут 20 сек на клиенте (`AbortController` в `app/page.tsx`) и 18 сек на сервере (`OpenAI({ timeout })`) для обоих AI-вызовов — при сбое сети или медленном ответе модели пользователь видит понятную ошибку максимум через ~20 сек, интерфейс не подвисает бесконечно.

**Не реализовано** (см. раздел 6 "Ограничения"): персистентное хранилище, авторизация, рекомендации задач от ИИ.

**Структура проекта:**

```
app/
  page.tsx               — весь клиентский интерфейс: выбор роли, сценарий бизнеса
                            (черновик → вопросы → карточка → публикация), каталог
                            и отклики команды. Один компонент-стейтмашина на React useState.
  layout.tsx              — корневой layout, метаданные страницы
  globals.css              — цветовые токены темы (фон, поверхности, акцент, danger)
  api/clarify/route.ts    — POST-эндпоинт: черновик → OpenAI (CLARIFY_PROMPT) → вопросы
  api/card/route.ts       — POST-эндпоинт: черновик + ответы → OpenAI (CARD_PROMPT) → карточка
lib/
  types.ts                — TypeScript-модели: Task, TaskCard, Team, TeamResponse
  rating.ts                — calculateRating(): детерминированная формула рейтинга
  prompts.ts                — CLARIFY_PROMPT и CARD_PROMPT — системные промпты для OpenAI
  seed.ts                   — синтетические данные: черновики, готовые карточки, команды, отклики
```

**Откуда данные:**
- Единственный внешний сервис — **OpenAI API** (модель `gpt-5.4-mini`), вызывается из двух серверных роутов.
- Демонстрационные данные каталога и откликов — из `lib/seed.ts`, подставляются в состояние при загрузке страницы.
- Всё остальное (задачи, созданные через форму, новые отклики) — живёт в состоянии React (`useState`) в рамках одной вкладки браузера; при перезагрузке страницы состояние сбрасывается к seed-данным.

**Переменные окружения** (проверено по `.env.example`):

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI API, обязателен для работы обеих AI-функций |

## 3. Что делает / как работает

Пошаговый сценарий, как он реально реализован в `app/page.tsx`:

1. **Выбор роли.** Пользователь видит экран с двумя кнопками — "Я представитель бизнеса" / "Я студенческая команда". Клик задаёт состояние `role`, дальше рендерится соответствующая часть интерфейса.

2. **Черновик (роль "бизнес").** Пользователь вводит текст в `textarea` или нажимает одну из кнопок "Пример 1–5" (автоподстановка из `SEED_DRAFTS`). По кнопке "Проанализировать черновик" вызывается `handleDraftSubmit`, которая отправляет `POST /api/clarify`.

3. **Уточняющие вопросы.** `app/api/clarify/route.ts` передаёт черновик в OpenAI с системным промптом `CLARIFY_PROMPT`, получает JSON вида `{ missing_categories, questions }` и возвращает его на клиент. Интерфейс показывает список вопросов с полями ввода.

4. **Сборка карточки.** После ответа на вопросы вызывается `handleAnswersSubmit` → `POST /api/card`. Роут передаёт черновик и пары "вопрос-ответ" в OpenAI с промптом `CARD_PROMPT`, получает структурированный JSON (название, тема, контекст, потребность, пользователи, данные, ограничения, ожидаемый результат, критерии успеха, контакт, формат) и список незаполненных полей.

5. **Рейтинг.** Сразу после получения карточки вызывается `calculateRating()` из `lib/rating.ts` — локально, без обращения к ИИ. Функция проверяет длину каждого поля (порог 8 символов) и начисляет баллы по весам: контекст+потребность — 20, данные — 20, результат — 15, критерии успеха — 15, ограничения — 10, пользователи — 10, связь с бизнесом — 10. Итог показывается с расшифровкой по каждой категории и подсказкой, что заполнить, если баллов не хватает.

6. **Редактирование и публикация.** Любое поле карточки можно изменить вручную — рейтинг пересчитывается на лету (`updateCardField`). По кнопке "Подтвердить и опубликовать" задача добавляется в общий каталог (`publishTask`), отсортированный по убыванию рейтинга.

7. **Каталог (роль "команда").** Список задач с фильтрами по теме и уровню готовности. Каждая карточка показывает прогресс-бар рейтинга, цветной бейдж готовности, превью ожидаемого результата и аудитории.

8. **Отклик.** Под каждой задачей — форма `TeamResponseForm`: выбор команды из списка, идея решения, план, ссылка на прототип. По отправке создаётся объект `TeamResponse` со статусом `pending`.

9. **Выбор бизнеса.** Переключившись обратно на роль "бизнес", пользователь видит раздел "Мои задачи и отклики" со всеми полученными откликами и может нажать "Выбрать команду" (статус → `accepted`) или "Отклонить" (статус → `declined`) — функция `decideResponse`. Автоматического назначения в коде нет.

## 5. Как проверить решение

Воспроизводимый сценарий с реальными данными из проекта:

1. Открыть главную страницу → выбрать **"Я представитель бизнеса"**.
2. Нажать **"Пример 1"** — подставится черновик *"Нужно автоматизировать проверку заявок клиентов"* → **"Проанализировать черновик"**.
3. Получить от 3 до 7 уточняющих вопросов (проверено живым вызовом: реальный ответ включал вопросы по всем 7 категориям для этого слабого черновика). Ответить хотя бы на 2–3 вопроса → **"Собрать карточку"**.
4. Убедиться, что карточка заполнилась только по данным ответов, а не заполненные поля остались пустыми (проверено: поля, на которые не отвечали, приходят в `missing_fields` и остаются пустой строкой).
5. Посмотреть рейтинг с расшифровкой по 7 категориям → изменить любое поле карточки → убедиться, что баллы пересчитались мгновенно.
6. Нажать **"Подтвердить и опубликовать в каталог"**.
7. Нажать **"Сменить роль"** → **"Я студенческая команда"**.
8. В каталоге (вместе с 5 демо-задачами) найти только что опубликованную, применить фильтры по теме/готовности, отправить отклик от имени любой из 5 команд.
9. Снова сменить роль на бизнеса → в разделе "Мои задачи и отклики" увидеть новый отклик → принять или отклонить.

## 6. Ограничения

Сознательно не реализовано, и почему:

- **Нет персистентного хранилища (БД).** Данные живут в состоянии React в рамках одной вкладки браузера. Раздел 7 Положения хакатона прямо исключает требование полноценной инфраструктуры для пятичасового MVP.
- **Нет авторизации и ролевой модели.** Вместо этого — простой переключатель роли без логина, по тем же основаниям.
- **ИИ-рекомендации задач студентам не реализованы.** Правилами (раздел 5 ТЗ) это разрешено, но не обязательно — приоритет отдан обязательному функционалу.
- **Тема задачи (`topic`) не имеет отдельного справочника** — определяется ИИ на этапе сборки карточки; фильтр в каталоге строится по темам, фактически встретившимся в данных.
- **Нет деплоя на Vercel на момент написания этого README** — проект проверен и работает только локально (`npm run dev`).
