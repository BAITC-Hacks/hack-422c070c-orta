# AI Sana Challenge Hub

**Трек «Образование» · HackAlem AI · Кейс: «AI Sana Challenge Hub: от бизнес-задачи к решению»**

## 1. Краткое описание

Представители бизнеса часто формулируют задачи для студенческих команд слишком коротко и абстрактно ("сделайте бота", "нужна автоматизация") — студентам трудно понять, за что браться и что именно нужно сделать.

**AI Sana Challenge Hub** — это MVP-платформа, которая решает эту проблему в четыре шага:

1. Бизнес пишет короткий черновик своей потребности.
2. ИИ задаёт уточняющие вопросы по тем аспектам, которые не раскрыты.
3. Из черновика и ответов собирается полноценная карточка задачи с прозрачным рейтингом качества (0–100).
4. Готовая задача публикуется в открытом каталоге, где любая студенческая команда может откликнуться, а бизнес — вручную выбрать, с кем работать.

Для кого: представители бизнеса (заказчики задач) и студенческие команды.

## 2. Что реализовано

| Модуль | Описание |
|---|---|
| Конструктор задачи | Свободный ввод черновика, ИИ-анализ полноты, ≥3 уточняющих вопроса по недостающим категориям |
| Карточка задачи | Собирается из черновика и ответов, редактируется вручную перед публикацией |
| Рейтинг задачи | Детерминированная формула 0–100 по 7 категориям, расшифровка баллов, 4 уровня готовности, пересчёт при любом изменении |
| Общий каталог | Все опубликованные задачи доступны всем командам, сортировка по рейтингу, фильтры по теме и уровню готовности |
| Отклики команд | Любая команда отправляет идею, план и ссылку на прототип; число откликов не ограничено |
| Выбор бизнеса | Ручное решение по каждому отклику (принять/отклонить); автоматическое назначение команды исключено логикой приложения |
| Роли без логина | При входе — выбор "Я бизнес" / "Я студенческая команда" (просто переключатель экрана, без аккаунтов и паролей); у каждой роли свой набор действий |
| Индикатор ИИ | Бейдж "ИИ-помощник заполнил по вашим ответам" на экране карточки — прозрачно показывает происхождение данных |

## 3. Как работает решение

Сквозной пользовательский сценарий:

1. **Черновик.** Представитель бизнеса вводит краткое описание потребности (или выбирает один из 5 готовых примеров).
2. **Уточнение.** ИИ анализирует черновик по 7 категориям (контекст и потребность, данные, ожидаемый результат, критерии успеха, ограничения, пользователи, связь с бизнесом) и задаёт минимум 3 вопроса по тем категориям, которые слабо раскрыты.
3. **Карточка.** Из черновика и ответов на вопросы ИИ собирает структурированную карточку. Поля, для которых данных недостаточно, остаются пустыми — модели запрещено додумывать факты.
4. **Рейтинг.** Приложение (не ИИ) начисляет баллы за каждую заполненную категорию по фиксированным весам, показывает итоговый балл, уровень готовности и подсказки, что именно повысит рейтинг.
5. **Публикация.** Представитель бизнеса подтверждает карточку — она попадает в общий каталог на позицию, соответствующую рейтингу.
6. **Отклик.** Любая студенческая команда просматривает каталог, использует фильтры по теме/готовности и отправляет отклик: идею решения, план и ссылку на прототип.
7. **Выбор.** Бизнес видит все отклики по своей задаче и вручную принимает или отклоняет каждый — без автоматического назначения.

## 4. Технологии

- **Next.js 16** (App Router) + **React 19** + **TypeScript**
- **Tailwind CSS 4** — цветовая тема на CSS-токенах (`app/globals.css`)
- **OpenAI API** (`openai`, модель `gpt-5.4-mini`) — единственный внешний AI-сервис, используется в двух функциях (уточняющие вопросы и сборка карточки)
- Деплой: **Vercel**

## 5. Архитектура проекта

```
app/
  page.tsx               — вся клиентская логика: выбор роли, сценарий бизнеса,
                            каталог и отклики команды (единый компонент-стейтмашина)
  api/clarify/route.ts   — POST: черновик → OpenAI (CLARIFY_PROMPT) → JSON с вопросами
  api/card/route.ts      — POST: черновик + ответы → OpenAI (CARD_PROMPT) → карточка
lib/
  types.ts               — модели Task, TaskCard, Team, TeamResponse
  rating.ts               — детерминированная формула рейтинга (чистая функция, без ИИ)
  prompts.ts              — системные промпты обеих AI-функций
  seed.ts                 — синтетические тестовые данные (см. раздел 9)
```

**Поток данных:**

```
Черновик ──POST /api/clarify──▶ OpenAI (CLARIFY_PROMPT) ──▶ вопросы
                                                                 │
                                                          пользователь отвечает
                                                                 │
                    ◀──POST /api/card── OpenAI (CARD_PROMPT) ◀──┘
                    │
              структурированная карточка
                    │
        lib/rating.ts (локально, без ИИ) ──▶ рейтинг + уровень готовности
                    │
              публикация в каталог (React state)
                    │
        отклик команды ──▶ ручной выбор бизнеса (accept/decline)
```

Рейтинг принципиально вынесен из зоны ответственности ИИ — это чистая детерминированная функция, что делает критерий "Геймификация бизнеса" полностью прозрачным и воспроизводимым.

## 7. Как проверить решение

1. Открыть главную страницу — выбрать роль **"Я представитель бизнеса"**.
2. Нажать **"Пример 1"** (слабый черновик: *"Нужно автоматизировать проверку заявок клиентов"*) → **"Проанализировать черновик"**.
3. Получить уточняющие вопросы, ответить на них → **"Собрать карточку"**.
4. Увидеть собранную карточку и рейтинг с расшифровкой по категориям; отредактировать любое поле — рейтинг пересчитается мгновенно.
5. Нажать **"Подтвердить и опубликовать в каталог"**.
6. Нажать **"Сменить роль"** → выбрать **"Я студенческая команда"**.
7. В каталоге найти опубликованную задачу (плюс 5 готовых демо-задач), попробовать фильтры по теме/готовности, отправить отклик от имени любой команды.
8. Снова сменить роль на бизнес — увидеть новый отклик в разделе "Мои задачи и отклики", принять или отклонить его.

Если `OPENAI_API_KEY` не задан или неверен — эндпоинты вернут явную ошибку авторизации (проверено обработкой в `app/api/clarify/route.ts` и `app/api/card/route.ts`), а не тихий сбой.

## 8. Данные и интеграции

- Единственная внешняя интеграция — **OpenAI API**.
- `lib/seed.ts` содержит полный набор синтетических данных по разделу 6 Положения (минимум 5 в каждой категории):
  - **5 черновиков** бизнес-задач разного качества, включая слабый — для демонстрации роста рейтинга на защите;
  - **5 готовых карточек** с реально рассчитанным рейтингом — представлены все 4 уровня готовности (100 / 80 / 55 / 40 / 20 баллов);
  - **5 профилей** студенческих команд (название, интересы, навыки, технологии);
  - **5 откликов** на задачи с разными статусами (pending / accepted / declined) — для демонстрации ручного выбора бизнеса.
- Каталог и отклики заполнены этими данными **сразу при открытии сайта** — не нужно вручную проходить весь сценарий, чтобы увидеть работающий каталог.

## 9. Ограничения

- Нет персистентного хранилища — каталог и отклики живут в состоянии React в рамках одной сессии браузера. Это осознанное решение: раздел 7 Положения прямо исключает требование полноценной инфраструктуры для пятичасового MVP.
- Нет авторизации и ролевой модели — вместо этого простой переключатель роли без логина, по тем же основаниям.
- ИИ используется только в двух функциях (уточняющие вопросы, сборка карточки) — не участвует в расчёте рейтинга и не выбирает команду за бизнес.
- Тема задачи (`topic`) определяется ИИ на этапе сборки карточки; отдельного справочника тем нет — фильтр в каталоге строится по темам, фактически встретившимся в данных.
