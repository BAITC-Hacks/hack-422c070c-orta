# Староста-агент

ИИ-агент, который берёт фото расписания или сообщение из WhatsApp-чата и сам доводит его до результата: записывает в базу, создаёт календарь и уведомляет группу в Telegram. Без ручной перепечатки.

Живая версия: https://starosta-agent.vercel.app
Код: https://github.com/BAITC-Hacks/hack-422c070c-orta

---

## 1. Проблема

В Казахстане около 600 тысяч студентов и 770 колледжей. Расписание живёт в Excel, чатах и на бумаге. Каждую неделю староста группы вручную перебивает таблицу из фото в телефон и пересылает по чатам. Студенты пропускают изменения, преподаватели ждут в пустых аудиториях.

Цена рутины: 1–2 часа в неделю на одну группу. В стране десятки тысяч групп, это сотни тысяч часов в семестр, потраченных на перепечатку.

## 2. Для кого

| Роль | Что получает |
|---|---|
| Староста группы | Загружает фото или текст один раз, остальное делает агент |
| Студенты группы | Уведомление в Telegram и календарь в телефоне |
| Куратор, деканат | Актуальное расписание всех групп в одной базе |

## 3. Что делает агент

Пользователь делает два действия: загружает источник и нажимает кнопку. Дальше агент работает сам:

| Шаг | Что происходит | Инструмент |
|---|---|---|
| 1 | Составляет план из шагов и пишет его на экран | текст модели |
| 2 | Распознаёт занятия из фото или текста в структуру: день, время, предмет, преподаватель, аудитория | `extract_schedule` |
| 3 | Проверяет результат: пересечения по времени, пустые поля, формат. При проблемах повторяет распознавание с уточнениями или исправляет сам, до 3 попыток | `validate_schedule`, `fix_schedule` |
| 4 | Записывает расписание в Supabase, старое расписание группы заменяет | `save_schedule` |
| 5 | Читает из базы обратно и сверяет количество. При расхождении сохраняет повторно | `verify_saved` |
| 6 | Создаёт файл календаря .ics с повторяющимися событиями на 16 недель | `create_calendar` |
| 7 | Отправляет сообщение в Telegram-группу студентов | `notify_group` |
| 8 | Пишет итог: сколько занятий, были ли повторы | текст модели |

Каждый шаг виден на экране в реальном времени. Если инструмент вернул ошибку, модель получает её как ошибку и сама решает: повторить, исправить или пойти дальше.

## 4. Архитектура

```
Пользователь ──▶ Next.js (app/page.tsx)
                     │  POST /api/agent, поток событий (SSE)
                     ▼
            Агентный цикл (app/api/agent/route.ts)
            Модель: план → выбор инструмента → оценка результата → повтор
            Провайдер: Claude (Anthropic) или OpenAI, выбирается по ключу в окружении
                     │
        ┌────────────┼──────────────┬──────────────┬──────────────┐
        ▼            ▼              ▼              ▼              ▼
 extract_schedule validate_schedule save_schedule create_calendar notify_group
 (модель с vision,  fix_schedule    verify_saved   (.ics)         (Telegram
  фото или текст,   (правила)       (Supabase)                     Bot API)
  structured output)
```

Файлы:

| Файл | Что внутри |
|---|---|
| `app/page.tsx` | Экран: форма, индикаторы подключений, живой лог, таблица результата, скачивание .ics |
| `app/api/agent/route.ts` | Агентный цикл, максимум 14 шагов, поток событий SSE, логирование запуска |
| `app/api/health/route.ts` | Проверка, какие интеграции настроены и какой провайдер модели активен |
| `lib/llm/` | Провайдеры: `anthropic.ts`, `openai.ts`, выбор в `index.ts` |
| `lib/tools/index.ts` | Описания семи инструментов и их выполнение |
| `lib/prompt.ts` | Системные промпты агента и распознавания |
| `lib/supabase.ts`, `lib/telegram.ts`, `lib/ics.ts` | Клиенты внешних систем и генератор календаря |
| `lib/types.ts` | Схема расписания (zod) и типы событий |
| `supabase/schema.sql` | Таблицы `schedules`, `lessons`, `agent_runs` |
| `scripts/test-tools.ts` | Офлайн-тесты инструментов, без вызова модели |

Режим заглушки: если Supabase или Telegram не настроены, соответствующий инструмент работает в памяти и явно пишет об этом в лог. Демо не падает, индикаторы в шапке показывают, что подключено.

## 5. Демо, сценарий на 2 минуты

1. Открыть https://starosta-agent.vercel.app. В шапке индикаторы: модель, Supabase, Telegram. Зелёные значит подключено.
2. Нажать «Вставить пример» или загрузить фото реального расписания. Указать группу.
3. Нажать «Запустить агента».
4. Смотреть лог справа. Ожидаемая последовательность:
   ```
   План: распознать, проверить, записать, сверить, календарь, уведомить
   ✓ Распознавание расписания: распознано N занятий
   ✓ Проверка конфликтов: конфликтов нет     (или ✗ проблемы → исправление → ↻ повтор → ✓)
   ✓ Запись в базу: N занятий в Supabase
   ✓ Сверка с базой: в базе N, совпадает
   ✓ Календарь .ics: N событий
   ✓ Уведомление группы: отправлено в Telegram
   Готово: N занятий сохранено, календарь создан, уведомление отправлено
   ```
5. Показать телефон: в Telegram-группе пришло сообщение.
6. Показать Supabase: Table Editor, таблица `lessons`, строки группы.
7. Нажать «Скачать .ics», открыть в календаре: занятия расставлены на семестр.

## 6. Стек

- Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4
- Модель: Claude (`@anthropic-ai/sdk`, `claude-opus-5` + `claude-sonnet-5`) или OpenAI (`openai`, модели задаются переменными). Оба провайдера используют вызов инструментов и structured output.
- Supabase (Postgres), Telegram Bot API, iCalendar (RFC 5545)
- Vercel

## 7. Запуск локально, пошагово

Нужны Node.js 20 или новее и git.

**Шаг 1. Клонировать и установить зависимости**
```bash
git clone https://github.com/BAITC-Hacks/hack-422c070c-orta.git
cd hack-422c070c-orta
npm install
```
Ожидаемый вывод: `added N packages` и `found 0 vulnerabilities`.

**Шаг 2. Создать файл окружения**
```bash
cp .env.example .env.local
```
Открыть `.env.local` в редакторе. Нужен ключ одного из провайдеров:
```
OPENAI_API_KEY=sk-...          # либо этот
ANTHROPIC_API_KEY=sk-ant-...   # либо этот
```
Если заданы оба, используется Claude. Принудительно выбрать: `LLM_PROVIDER=openai` или `LLM_PROVIDER=anthropic`.
Остальные переменные (Supabase, Telegram) по желанию, см. раздел 9. Без них агент работает в режиме заглушки.

**Шаг 3. Проверить инструменты без вызова модели**
```bash
npm test
```
Ожидаемый вывод: 12 строк с ✓ и в конце `Все проверки пройдены`.

**Шаг 4. Запустить**
```bash
npm run dev
```
Ожидаемый вывод: `Ready in ...ms` и адрес `http://localhost:3000`. Если порт занят: `npm run dev -- -p 3005`.

**Шаг 5. Открыть в браузере**
http://localhost:3000. В шапке индикатор модели должен быть зелёным. Нажать «Вставить пример», затем «Запустить агента». Через 20–40 секунд лог дойдёт до строки «Готово».

**Шаг 6. Проверить API напрямую (по желанию)**
```bash
curl http://localhost:3000/api/health
```
Ожидаемый ответ: `{"provider":"openai","supabase":"off","telegram":false}` (или `"anthropic"`, `"ok"`, `true`, если настроены).

## 8. Деплой на Vercel, пошагово

**Способ А, через сайт**
1. Зайти на https://vercel.com/new, войти через GitHub.
2. Нажать «Import» напротив репозитория `hack-422c070c-orta`. Если репозиторий не виден, нажать «Adjust GitHub App Permissions» и дать доступ к организации.
3. В блоке «Environment Variables» добавить ключ провайдера и, если есть, переменные Supabase и Telegram.
4. Нажать «Deploy». Через 1–2 минуты появится ссылка вида `https://<имя>.vercel.app`.
5. Открыть ссылку, убедиться, что индикатор модели зелёный.

**Способ Б, через терминал**
```bash
npm i -g vercel
vercel login                                 # откроется браузер
vercel link                                  # привязать папку к проекту
vercel env add OPENAI_API_KEY production     # спросит значение, вставить ключ
vercel --prod                                # деплой
```
Ожидаемый вывод последней команды: строка `Production: https://...vercel.app`.

Если Vercel пишет «commit author doesn't have permission», значит email в git не совпадает с аккаунтом Vercel. Либо `git config user.email <email аккаунта Vercel>`, либо задеплоить без git-метаданных:
```bash
mv .git .git-off && vercel --prod --yes; mv .git-off .git
```

## 9. Переменные окружения и настройка интеграций

| Переменная | Обязательна | Что делает |
|---|---|---|
| `OPENAI_API_KEY` | один из двух | Ключ OpenAI |
| `ANTHROPIC_API_KEY` | один из двух | Ключ Claude API |
| `LLM_PROVIDER` | нет | `openai` или `anthropic`, если заданы оба ключа |
| `OPENAI_MODEL`, `OPENAI_EXTRACT_MODEL` | нет | Модели OpenAI для агента и распознавания, по умолчанию `gpt-5` и `gpt-5-mini` |
| `SUPABASE_URL` | нет | Адрес проекта Supabase |
| `SUPABASE_SERVICE_KEY` | нет | Ключ service_role для записи в базу |
| `TELEGRAM_BOT_TOKEN` | нет | Токен бота |
| `TELEGRAM_CHAT_ID` | нет | Id группы, куда слать уведомления |

**OpenAI**
1. https://platform.openai.com/api-keys, «Create new secret key». Скопировать в `OPENAI_API_KEY`.
2. Убедиться, что на аккаунте есть баланс: https://platform.openai.com/settings/organization/billing.

**Claude API**
1. https://platform.claude.com/settings/billing, пополнить баланс.
2. https://platform.claude.com/settings/keys, «Create key», Scope: Default workspace. Скопировать в `ANTHROPIC_API_KEY`.

**Supabase**
1. https://supabase.com, «New project», любое имя, регион ближайший.
2. Слева «SQL Editor», «New query», вставить содержимое файла `supabase/schema.sql`, нажать «Run». Ожидаемо: `Success. No rows returned`.
3. Слева «Project Settings», «API». Скопировать «Project URL» в `SUPABASE_URL` и ключ «service_role» в `SUPABASE_SERVICE_KEY`.
4. Проверка: `curl http://localhost:3000/api/health` должен вернуть `"supabase":"ok"`.

**Telegram**
1. В Telegram открыть @BotFather, команда `/newbot`, задать имя и username. Скопировать токен в `TELEGRAM_BOT_TOKEN`.
2. Создать группу студентов, добавить бота в участники, написать в группу любое сообщение.
3. Открыть в браузере `https://api.telegram.org/bot<токен>/getUpdates`. Найти `"chat":{"id":-100...}`. Это число со знаком минус скопировать в `TELEGRAM_CHAT_ID`.
4. Проверка: `curl http://localhost:3000/api/health` должен вернуть `"telegram":true`.

После изменения `.env.local` перезапустить `npm run dev`. На Vercel после добавления переменных сделать новый деплой.

## 10. Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| Ошибка «Нет ключа модели в окружении» | Ключ не задан или сервер не перезапущен | Проверить `.env.local`, перезапустить `npm run dev` |
| Ошибка «Неверный ключ» | Ключ с опечаткой или отозван | Создать новый ключ |
| Ошибка про лимит запросов | Нет баланса или превышен лимит | Пополнить баланс, подождать минуту |
| Индикатор «Supabase: ошибка» | Схема не выполнена или неверный ключ | Выполнить `supabase/schema.sql`, проверить service_role |
| Уведомление «в режиме заглушки» | Telegram не настроен | Раздел 9, пункт Telegram |
| «Фото больше 4 МБ» | Слишком большой файл | Сжать или обрезать фото |
| Порт 3000 занят | Другой сервер | `npm run dev -- -p 3005` |

## 11. Что написано до хакатона

Каркас Next.js с одной формой и одним вызовом Claude без инструментов (репозиторий `884mk22cdh-dev/hackathon-template`, публичный). Из него взяты структура проекта, конфиги и стили формы.

Написано на хакатоне: агентный цикл с планированием, проверкой и повторами; семь инструментов; распознавание фото и текста со structured output; два провайдера модели; интеграции Supabase и Telegram; генерация календаря; потоковый лог событий; экран агента; офлайн-тесты; схема базы; README и питч.

## 12. Что дальше

- Бот сам читает Telegram-группу: староста вообще ничего не загружает, агент реагирует на сообщение с расписанием.
- Изменения: агент сравнивает новую версию со старой и уведомляет только о разнице.
- Посещаемость: преподаватель фотографирует журнал, агент заполняет ведомость по той же схеме.
- Интеграция с системами колледжей через экспорт и открытые данные.
- Дорога к продукту: колледж как клиент, 770 колледжей, в каждом десятки групп.
