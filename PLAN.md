# План. Староста-агент

## Сценарий демо (2 минуты)
1. Староста открывает сайт, загружает фото расписания (или вставляет текст из WhatsApp), выбирает группу.
2. Нажимает «Запустить агента».
3. На экране появляется живой лог: план → распознавание → проверка → запись в базу → календарь → уведомление → итог.
4. В Telegram-группе приходит сообщение с расписанием, в Supabase появляются записи, скачивается .ics.

## Архитектура агента
Цикл `while stop_reason == "tool_use"` в `app/api/agent/route.ts`:
- Модель получает системный промпт с ролью и порядком действий.
- Инструменты (каждый в `lib/tools/`):
  - `extract_schedule` — принимает изображение или текст, возвращает JSON занятий (день, время, предмет, преподаватель, аудитория).
  - `validate_schedule` — проверяет пересечения по времени, пустые поля, формат времени. Возвращает список проблем. Если проблемы есть, агент чинит и вызывает снова (повторная попытка).
  - `save_schedule` — пишет в Supabase `schedules` + `lessons`. Без ключей: заглушка с пометкой.
  - `create_calendar` — генерирует .ics, возвращает ссылку на скачивание.
  - `notify_group` — шлёт сообщение в Telegram. Без токена: заглушка.
  - `verify_saved` — читает из базы обратно и сверяет количество занятий. Несовпадение → повтор save.
- Каждый вызов инструмента и результат пишется в лог `agent_runs` и стримится на экран через SSE.

## Экран
Одна страница: слева форма (фото/текст, группа, кнопка), справа лог шагов с иконками статуса и итоговая карточка (сколько занятий, ссылка на .ics, статус уведомления).

## Порядок работы
1. Инструменты и цикл агента, режим заглушек. Сборка.
2. Экран с логом через SSE.
3. Подключение Supabase и Telegram, реальный прогон с фото.
4. README, деплой, проверка на чистом клоне.
5. Репетиция демо.
